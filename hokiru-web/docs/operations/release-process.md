# リリースプロセス

## Phase 0: 基盤構築（人間のみ可能な1回きりのセットアップ）

- 認証情報メモのパスワードマネージャ移行
- claude.aiでの定時タスク設定（毎朝ループ・週次レビュー）
- GitHub Actions初回認可・`.github/`をリポジトリ直下へ配置し各種secretsを登録
  （現状は`hokiru-web/.github/`にテンプレートとして格納 — 動作させるにはリポジトリ直下へ
  移動する必要がある。詳細は`hokiru-web/README.md`参照）
- 独立リポジトリへの切り出しとIssuesの有効化（現在のホストリポジトリはIssuesが無効化されて
  いるため、判断キューの一次ソースを`decision-queue.md`/Notionから GitHub Issueへ移行するには
  この切り出しが前提になる）
- Notion API連携の認可（またはNotion MCPの有効化）
- Vercel・Supabaseの初回接続
- PRの最終マージ判断
- 監修済み問題として公開する最終判断

**完了条件**: 夜間ランが1本目のPRを無人で作成できたこと（v1.0 §6 Phase 0）。

## Phase 1: 品質到達ループ稼働

- 夜間ランがDoDを消化し、人間はスクリーンショット判定とマージのみ行う
- 並行して、AI生成問題の監修（一級建築士本人によるレビュー）を進める

**完了条件**: `docs/operations/dod.md` の残数0。

## Phase 2: 公開

- 独自ドメイン・Stripe・LP公開（判断キュー: 価格・課金方式・公開日）

**完了条件**: 外部ユーザー10人 または 初収益。

## Phase 3: 発信の定常化

- 下書き全自動化、人間は送信のみ。取得実録noteの有料化。

## Phase 4: 横展開（資格学習ファクトリー第2号機）

- 次に取得する資格を1つ選定し、HOKIRU Webのテンプレートを再利用する。
